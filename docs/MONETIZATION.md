# «Плюс» — платная версия: решения и план реализации

Составлено 9 октября 2026. Исследование конкурентов, на которое опирается план, — в [COMPETITORS.md](COMPETITORS.md); публикация в RuStore — в [RUSTORE.md](RUSTORE.md).

## Решение

**Бесплатно — всё, что нужно для нормальной работы. Платно («Плюс») — украшения и дополнительные уведомления.**

| Бесплатно                                                                    | «Плюс»                                                                                             |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Расписание, звонки, неделя, окна, отсчёт до звонка                           | **Цветовые выделения:** цвета предметов и классов, свои цветовые метки, цветная полоска в виджетах |
| Каникулы, праздники, сокращённые дни, заметки и чек-листы к урокам           | **Акцентный цвет интерфейса** (кроме основного зелёного)                                           |
| Виджет на компьютере со всеми настройками окна, трей, автозапуск, обновления | **Уведомления на телефоне:** перед уроком, перед концом урока, сводка на завтра                    |
| Светлая, тёмная и системная тема                                             | **Выбор звука** (перезвон, вибрация, беззвучно) и «Не звенеть на уроке»                            |
| Перенос по QR-коду, резервные копии                                          |                                                                                                    |
| Виджеты на рабочем столе телефона                                            |                                                                                                    |
| **Утренняя сводка** на телефоне — какие сегодня уроки                        |                                                                                                    |

Позже ценность «Плюса» стоит поднять функциями, которых нет ни у одного конкурента: темы уроков по КТП, учёт замен и нагрузки (см. [COMPETITORS.md](COMPETITORS.md)).

## Решения (13 октября 2026)

1. **Урок в шторке** — бесплатно.
2. **Напоминание перед звонком на компьютере** — бесплатно, как сейчас.
3. **Цена** — **300 ₽, навсегда**, разовая покупка.
4. **Первая версия — только бесплатное.** Платные функции скрыты (`PLUS_ON_SALE = false` в `src/plus.ts`) и появятся обновлением как «Плюс». Никто ничего не теряет — подарок не нужен.
5. **Название** — «Расписание учителя».

## Как это выглядит для учителя

- Бесплатная версия работает полностью. Платные функции видны на своих местах со значком **«Плюс»**: можно открыть, посмотреть пример (как выглядят цвета, как выглядит уведомление) — и кнопка **«Подключить Плюс — N ₽»**.
- **Покупка:** «Подключить» → открывается страница оплаты Робокассы в браузере → оплата картой или СБП → вернуться в приложение → «Плюс» включился сам, вводить ничего не нужно.
- **Одна покупка — все устройства учителя.** Ключ «Плюса» переносится на компьютер или другой телефон вместе с QR-кодом и резервной копией. Можно и ввести ключ вручную: «У меня есть ключ».
- **Потеряли ключ** (новый телефон без копии) — «Восстановить покупку» по номеру заказа из чека Робокассы.
- Ни аккаунта, ни регистрации. В интернет приложение выходит только во время покупки и восстановления.

## Как устроена оплата

```text
Приложение                    Облачная функция                   Робокасса
───────────                   ────────────────                   ─────────
«Подключить Плюс»
  ├─ POST /order ───────────►  создаёт заказ: номер, товар,
  │   (секрет заказа)          сумма, хеш секрета; подписывает
  │                            ссылку Паролем №1
  ◄─────────── ссылка ─────────┘
  ├─ открывает ссылку в браузере ───────────────────────────────►  оплата, чек через
  │                                                                «Робочеки СМЗ»
  │                            POST /robokassa/result  ◄──────────  уведомление
  │                            проверка подписи Паролем №2,
  │                            сумма = цене, заказ ещё не оплачен
  │                            → выпускает ключ, ответ «OK{InvId}»
  │                            Success URL: «Оплачено, вернитесь
  │                            в приложение» ◄──────────────────── переадресация
  └─ GET /license?order&secret  (раз в несколько секунд, пока
      ◄──────── ключ ───────────  открыт экран покупки)
проверяет подпись ключа, сохраняет — дальше без интернета
```

**Ключ «Плюса»** — `base64url(данные).base64url(подпись)`, где данные — `{ v: 1, order, product: "plus", until: null | "ГГГГ-ММ-ДД", issued }`, подпись — Ed25519. Закрытый ключ подписи хранится только в облаке (Yandex Lockbox), открытый — в приложении. Подделать ключ без закрытого нельзя; проверка в приложении — без интернета, библиотекой `@noble/ed25519` (работает одинаково на Windows, Android и в браузерном предпросмотре).

**Где работает сервер.** Yandex Cloud Functions + Object Storage (данные в России). При продажах в сотни штук в месяц укладывается в бесплатный объём. Хранится только: номер заказа, товар, сумма, статус, хеш секрета заказа, ключ. **Почты, имени и телефона у нас нет** — их для чека получает Робокасса, поэтому мы не становимся оператором персональных данных.

**Безопасность.** Подпись Робокассы проверяется Паролем №2 без учёта регистра; сумма сверяется с ценой товара; повторное уведомление по тому же заказу не выпускает второй ключ; ключ отдаётся только тому, кто знает секрет заказа (его создало приложение). Пароли Робокассы и закрытый ключ — в Lockbox, не в коде.

## Что делает автор (юридическое и организационное)

1. **Самозанятость** — уже есть. Лимит дохода — 2,4 млн ₽ в год. Продажу ключей к собственной программе на НПД один раз подтвердить у бухгалтера или в ФНС.
2. **Сайт продавца** — Робокасса подключает только работающий публичный сайт без переадресации. Сделаем на GitHub Pages (или своём домене, ~200 ₽ в год): описание приложения и «Плюса», цена, **оферта** (что покупается, как получить, как вернуть деньги), политика конфиденциальности, **почта и телефон для связи**, в подвале — **ФИО полностью и ИНН**. Тексты подготовлю я.
3. **Робокасса** — кабинет самозанятого, «Робочеки СМЗ» (чек в «Мой налог» и покупателю формируется сам), магазин: алгоритм подписи SHA-256, Result URL, Success URL, Fail URL, тестовые пароли. Модерация сайта — обычно до одного рабочего дня.
4. **Yandex Cloud** — аккаунт с платёжным аккаунтом (физлицо): функции, хранилище, Lockbox.
5. **RuStore** — письмо в поддержку (ниже) до того, как включать оплату.

## RuStore

**Сначала в RuStore — бесплатная версия, «Плюс» — обновлением** ([STRATEGY.md](STRATEGY.md)). Кто поставил приложение до «Плюса», получает его в подарок, так что никто ничего не теряет; с выходом «Плюса» карточка честно говорит, что бесплатно, а что нет. Правила RuStore требуют, чтобы часть функций была доступна без покупки и чтобы пользователь заранее знал, что и сколько стоит, а также «подробную информацию об оплате, получении и возврате».

**Письмо в поддержку** (support@rustore.ru) — отправить сразу, ответ определяет вариант:

```text
Здравствуйте! Я разработчик приложения «<название>» (пакет ru.teachercompanion.app), аккаунт физического лица.
Приложение бесплатное. Планируем разовую покупку дополнительных функций (оформление и дополнительные уведомления).
Оплату будем принимать как самозанятый через Робокассу: в приложении кнопка «Подключить» открывает нашу страницу
оплаты в браузере, после оплаты функции включаются. Чек формирует Робокасса через «Мой налог».

1. Допускается ли в приложении от аккаунта физического лица кнопка, ведущая на собственную страницу оплаты
   (Робокасса) для покупки функций этого приложения?
2. Если нет — допускается ли в приложении поле для ключа активации, купленного на нашем сайте, без кнопки покупки?
3. Если для продажи функций нужен переход на ИП и платёжные инструменты RuStore — какая комиссия и сохранятся ли
   приложение, отзывы и установки при переводе аккаунта?
```

**Варианты по ответу:**

- **А. Можно** — делаем, как описано выше, одинаково для всех платформ.
- **Б. Можно только ввод ключа** — в версии из RuStore нет кнопки покупки, есть «У меня есть ключ»; покупка — на сайте. Приложение уже различает установку из RuStore (`installSource()`), так что это одна проверка.
- **В. Нужны платёжные инструменты RuStore** — ИП, плагин RuStore Pay SDK для версии из RuStore (комиссия RuStore), Робокасса — для Windows и APK с GitHub. Ключ «Плюса» общий, только выдаётся из двух источников.

## Риски

- **Обход проверки.** Опытный пользователь Windows может подправить данные приложения. Принимаем: защищаемся от случайного, а не от упорного; честные учителя платят.
- **Ключ передадут коллеге** вместе с резервной копией. Принимаем: привязка к устройству усложнила бы жизнь честным и потребовала бы аккаунтов.
- **RuStore откажет** во внешней оплате — варианты Б и В выше.
- **Недовольство после обновления** — в первой версии платных функций нет, отнимать нечего; при выходе «Плюса» — честное описание в релизе.
