# PRD — Teacher Companion / «Помощник учителя»

## Принятые уточнения — актуально для текущей версии

Этот раздел имеет приоритет над первоначальными формулировками ниже.

- В MVP входят все описанные настройки и мастер первого запуска, кроме расширенного режима.
- Расписание вводится вручную отдельно для понедельника–пятницы. Суббота и воскресенье — выходные. Следующий учебный день определяется наличием уроков.
- Пустая неделя: сообщение «Расписание пока пустое» и доступ к редактору; поиск следующего дня возвращает отсутствие результата.
- Обновление даты после полуночи; после сна необходимо проверить актуальность даты.
- Общие звонки можно переопределить для отдельного урока. Минимальные обязательные поля — номер и класс; время можно настроить позже.
- Один номер урока в день, без пересечений известных временных интервалов. Порядок определяется номером. Окна — пропущенные номера между занятиями.
- Выбор дня в виджете (с 0.3.0): в учебный день виджет показывает **сегодня**, пока не закончился последний урок с известным временем, затем — следующий учебный день. Если время уроков сегодня неизвестно, сразу показывается следующий учебный день. Ручной выбор «Сегодня» / «Завтра» в виджете или в трее действует до конца текущих суток.
- Заметки и задачи не входят в MVP.
- По умолчанию компактный размер, правый верхний угол, тёмная тема, непрозрачность 100%, свободное перетаскивание, поверх всех окон выключено, закрытие в трей. Автозапуск выбирается при первом запуске.
- В MVP предусмотрены экспорт резервной копии и восстановление из файла.
- Поставка — установщик NSIS для текущего пользователя (без прав администратора) и дополнительно `.exe` без установки. Данные в обоих случаях хранятся в профиле пользователя, а не рядом с `.exe`. Репозиторий: https://github.com/kuzmin-lemmi/Teacher_Companion.
- Релизы собираются в GitHub Actions на Windows по тегу `vX.Y.Z`. Версия задаётся только в `package.json`; `tauri.conf.json` ссылается на него, `Cargo.toml` и `Cargo.lock` синхронизируются командой `npm version`.
- CI проверяет фронтенд (тесты, сборка, форматирование) и Rust (`cargo fmt`, `cargo clippy`).
- Самое перспективное направление развития — сбор домашних заданий через бота в MAX (раздел 55). Это отдельный модуль, выключенный по умолчанию; в текущую реализацию он не входит.

### Текущая реализация

Версия 0.2.0 — первая стабильная: прошла ручную приёмку на Windows (см. `docs/WINDOWS-CHECKLIST.md`). Реализованы SQLite и логика расписания, редакторы уроков и звонков, виджет, настройки окна, трей и автозапуск, темы, мастер первого запуска, экспорт и восстановление резервных копий, установщик. В 0.3.0 добавлен автоматический выбор дня «сегодня / следующий учебный день». Дальнейшие планы — в `docs/ROADMAP.md`.

# 2. Проблема

У школьного учителя есть повторяющиеся ежедневные задачи.

Одна из самых частых — каждый день помнить:

- какие уроки будут завтра;
- какие классы будут завтра;
- во сколько начинаются занятия;
- есть ли окна;
- сколько всего уроков;
- какие уроки требуют дополнительной подготовки.

Обычно для этого приходится:

- открывать электронный журнал;
- искать фотографию расписания;
- смотреть Excel-файл;
- открывать школьный сайт;
- вспоминать расписание самостоятельно;
- держать расписание на бумаге.

Это создаёт ненужную нагрузку.

Учителю нужен небольшой постоянно доступный помощник, который автоматически показывает информацию о следующем рабочем дне.

---

# 3. Цель продукта

Создать простое настольное приложение, которое запускается вместе с Windows и ненавязчиво показывает в правом верхнем углу экрана расписание учителя на следующий учебный день.

Приложение должно требовать минимум действий со стороны пользователя.

Основной сценарий:

> Учитель включает компьютер и сразу видит, какие уроки у него завтра.

---

# 4. Видение продукта

В будущем приложение должно стать персональной информационной панелью учителя.

Первая функция:

**Расписание на завтра.**

В дальнейшем:

- ежедневные дела;
- напоминания;
- заметки к урокам;
- контрольные;
- домашние задания;
- подготовка материалов;
- журнал;
- уведомления;
- расписание мероприятий;
- замены уроков;
- задачи на день;
- информация о классах.

Итоговая идея:

> Teacher Companion — небольшой персональный рабочий центр учителя, постоянно находящийся на рабочем столе.

---

# 5. Целевая аудитория

Основная аудитория:

- школьные учителя;
- преподаватели колледжей;
- преподаватели дополнительного образования.

Первая версия проектируется прежде всего для одного конкретного пользователя — школьного учителя.

Поддержка многопользовательского режима в MVP не требуется.

---

# 6. Основной пользовательский сценарий

Учитель включает компьютер.

После входа в Windows автоматически запускается Teacher Companion.

В правом верхнем углу появляется компактный виджет.

Пример:

```text
┌──────────────────────────────┐
│ Завтра · Пятница, 25 сентября │
│                              │
│ 1 · 08:30 · 6А               │
│ 2 · 09:20 · 7Б               │
│ 4 · 11:10 · 5А               │
│ 5 · 12:05 · 8В               │
│                              │
│ 4 урока                      │
└──────────────────────────────┘
```

Учителю не нужно нажимать дополнительные кнопки.

---

# 7. Логика определения дня

Приложение должно показывать не просто календарное «завтра», а следующий учебный день.

Примеры.

## Четверг

Показывается расписание пятницы.

## Пятница

Если в субботу занятий нет, показывается расписание понедельника.

## Суббота

Показывается расписание понедельника.

## Воскресенье

Показывается расписание понедельника.

Приложение должно иметь понятие:

**Следующий учебный день.**

> **Уточнение 0.3.0.** Утром учебного дня учителю нужно сегодняшнее расписание, а не завтрашнее. Поэтому в учебный день виджет показывает сегодняшний день до окончания последнего урока и только потом переключается на следующий учебный день.

---

# 8. MVP

Первая версия должна быть максимально простой.

В MVP входят:

1. хранение недельного расписания;
2. отображение расписания следующего учебного дня;
3. компактный desktop-виджет;
4. запуск вместе с Windows;
5. системный трей;
6. настройка расписания;
7. переключение «Сегодня / Следующий учебный день»;
8. сохранение настроек локально;
9. тёмная тема;
10. корректная работа без интернета.

---

# 9. Основной экран

Виджет располагается по умолчанию в правом верхнем углу.

Пример:

```text
┌──────────────────────────────┐
│ Пятница · 25 сентября       │
│ Следующий учебный день      │
│                              │
│ 08:30   6А                  │
│ 09:20   7Б                  │
│ 11:10   5А                  │
│ 12:05   8В                  │
│                              │
│ Всего: 4 урока              │
└──────────────────────────────┘
```

---

# 10. Информация об уроке

Каждый урок может содержать:

- номер урока;
- время начала;
- время окончания;
- класс;
- предмет;
- кабинет;
- короткую заметку.

Минимально обязательные поля:

```text
Номер урока
Класс
```

---

# 11. Расширенная карточка урока

В дальнейшем карточка может выглядеть так:

```text
2 урок

09:20–10:05

7Б
Информатика
Кабинет 312

⚠ Контрольная работа
```

В MVP заметка может быть необязательной.

---

# 12. Окна между уроками

Если между уроками есть свободное время, приложение должно уметь это визуально показывать.

Например:

```text
1 · 6А
2 · 7Б

──────── Окно ────────

4 · 8А
5 · 5Б
```

Это позволяет сразу понять структуру рабочего дня.

---

# 13. Дни без занятий

Если следующий день является выходным:

```text
Сегодня занятий больше нет.

Следующий учебный день:
Понедельник, 28 сентября
```

После этого показывается расписание понедельника.

---

# 14. Интерфейс

Главный принцип:

**минимум визуального шума.**

Приложение должно выглядеть как часть рабочего стола, а не как отдельная большая программа.

Требования:

- компактность;
- скруглённые углы;
- современный интерфейс;
- мягкая тень;
- полупрозрачность;
- хорошая читаемость;
- отсутствие лишних элементов;
- корректная работа на Full HD и 2K экранах.

---

# 15. Поведение окна

Виджет должен поддерживать:

### Always on top

Опционально приложение может находиться поверх остальных окон.

Настройка должна включаться и выключаться.

### Перетаскивание

Учитель может перетащить виджет в другое место экрана.

Позиция сохраняется.

### Закрепление

Можно включить режим:

**Закрепить виджет.**

После этого его невозможно случайно переместить.

### Прозрачность

Настраиваемая прозрачность:

```text
80%
90%
100%
```

---

# 16. Размеры

Предусмотреть минимум три режима.

### Компактный

```text
Завтра

1 · 6А
2 · 7Б
4 · 5А
```

### Обычный

Показывается время и дополнительная информация.

### Расширенный

Показываются заметки и дополнительные блоки.

Для MVP достаточно компактного и обычного режимов.

---

# 17. Переключение дней

В нижней или верхней части виджета:

```text
‹ Сегодня    Завтра ›
```

Или:

```text
Сегодня | Следующий день
```

Пользователь может быстро посмотреть сегодняшнее расписание.

Какой день показан по умолчанию, виджет выбирает сам (см. раздел 7). Ручное переключение действует до конца суток.

---

# 18. Настройка расписания

В приложении должна быть отдельная страница:

**Настройки → Расписание**

Пример:

```text
Понедельник

1 урок
08:30–09:15
6А
Информатика

2 урок
09:25–10:10
7Б
Информатика
```

Пользователь может:

- добавить урок;
- удалить урок;
- изменить класс;
- изменить время;
- изменить кабинет;
- изменить предмет;
- изменить порядок.

---

# 19. Настройка звонков

Расписание звонков желательно хранить отдельно.

Например:

```text
1 урок 08:30–09:15
2 урок 09:25–10:10
3 урок 10:20–11:05
4 урок 11:25–12:10
5 урок 12:20–13:05
```

При добавлении урока пользователь выбирает только номер урока.

Время подставляется автоматически.

---

# 20. Формат данных

Все данные должны храниться локально.

Пример структуры:

```json
{
  "schedule": {
    "monday": [
      {
        "lesson": 1,
        "class": "6А",
        "subject": "Информатика",
        "room": "312"
      },
      {
        "lesson": 2,
        "class": "7Б",
        "subject": "Информатика",
        "room": "312"
      }
    ]
  }
}
```

---

# 21. Расписание звонков

Пример:

```json
{
  "lessonTimes": {
    "1": {
      "start": "08:30",
      "end": "09:15"
    },

    "2": {
      "start": "09:25",
      "end": "10:10"
    }
  }
}
```

---

# 22. Хранение данных

Для MVP допустимо:

- JSON;
- SQLite.

Рекомендуемый вариант:

**SQLite.**

Причина:

в будущем появятся:

- напоминания;
- заметки;
- задачи;
- история;
- исключения;
- контрольные;
- расписание замен.

SQLite позволит не менять архитектуру приложения позднее.

# 37. Интеграция с электронным журналом

В перспективе приложение может получать:

- расписание;
- замены;
- домашние задания;
- изменения кабинетов;
- мероприятия.

Но продукт не должен зависеть от конкретного электронного журнала.

Основная архитектура должна оставаться автономной.

---

# 38. Работа без интернета

Основной функционал должен полностью работать локально.

Интернет не требуется для:

- просмотра расписания;
- редактирования расписания;
- заметок;
- задач;
- настроек.

# 49. Конфиденциальность

Все данные по умолчанию хранятся только на компьютере пользователя.

Никакие данные не отправляются на внешний сервер.

Для первой версии:

- не требуется аккаунт;
- не требуется регистрация;
- не требуется облако.

Исключение — модуль сбора домашних заданий (раздел 55). Он выключен по умолчанию и включается учителем вручную. Расписание при этом на сервер не отправляется.

# 55. Перспективное направление: сбор домашних заданий

Самое интересное направление развития. Отвечает на вопрос из раздела 54: учитель видит не только завтрашние уроки, но и сколько работ ему прислали к каждому из них.

Статус: идея, не входит в текущую реализацию. Пилот — один класс, работы присылают только знакомые ученики.

## Сценарий

1. Учитель выдаёт домашнее задание в «Дневник.ру», как обычно.
2. Ученик решает задание и отправляет боту в MAX архив с именем `Фамилия_Имя_Класс.zip`, например `Иванов_Иван_7Б.zip`.
3. Бот проверяет имя архива и сразу отвечает:

```text
✅ Принято: Иванов Иван, 7Б
```

или

```text
❌ Назовите архив так: Фамилия_Имя_Класс.zip
Например: Иванов_Иван_7Б.zip
```

4. В виджете у урока появляется счётчик присланных работ:

```text
ЗАВТРА

1 · 6А
2 · 7Б   📥 18 из 25
4 · 5А
```

5. По нажатию на счётчик виджет показывает пофамильный список тех, кто прислал работу к этому уроку.
6. Кнопка «Распаковать» скачивает архивы и распаковывает их по папкам учеников:

```text
Домашние задания\
  7Б\
    2026-09-25\
      Иванов Иван\
      Петрова Мария\
```

## Принятые решения

- **Канал — бот в MAX.** Учитель регистрирует бота на платформе MAX как самозанятый; бот проходит модерацию платформы.
- **Сервер — VPS в России.** Данные учеников хранятся на территории РФ (152-ФЗ). Vercel и зарубежные хостинги не используются.
- **Принимаются только архивы `.zip`** с именем `Фамилия_Имя_Класс.zip`. Остальные файлы бот отклоняет с подсказкой.
- **Список класса не ведётся.** Учитель задаёт в виджете только количество учеников в классе (например, 7Б — 25). Фамилия и имя берутся из имени архива.
- **Расписание остаётся на компьютере учителя.** Сервер хранит только: кто, из какого класса, когда и какой архив прислал. К какому уроку относится работа, определяет виджет.
- **Распаковывает виджет**, а не бот: бот работает на VPS и не имеет доступа к компьютеру учителя.
- **Модуль выключен по умолчанию.** Без него приложение остаётся полностью офлайн.

## Правила

### Имя архива

- Формат: `Фамилия_Имя_Класс.zip`, три части через подчёркивание.
- Фамилия и имя — кириллица, допускается дефис (`Римская-Корсакова`).
- Класс — номер 1–11 и буква: `7Б`. Регистр буквы не важен: `7б` и `7Б` — один класс.
- Класс из архива сопоставляется с классом в расписании после нормализации: верхний регистр, без пробелов и дефисов (`7-б` → `7Б`).

### Привязка к уроку

- Работа относится к ближайшему уроку этого класса, который начинается после отправки.
- Счётчик «N из M»: N — число разных учеников (по фамилии и имени), приславших работу к уроку; M — количество учеников, заданное учителем.
- Повторная отправка тем же учеником к тому же уроку заменяет предыдущую.

### Распаковка

- Путь: `<папка ДЗ>\<Класс>\<дата урока>\<Фамилия Имя>\`. Папка ДЗ задаётся в настройках.
- Распаковка выполняется на стороне Rust.
- Файлы не могут быть записаны за пределы папки ученика (защита от путей вида `..\`).
- Ограничение размера архива и распакованного содержимого.
- Имена папок очищаются от недопустимых в Windows символов.

## Архитектура

```text
Ученик ──zip──▶ Бот в MAX ──webhook (HTTPS)──▶ VPS
                                               ├─ проверка имени архива
                                               ├─ хранение архивов
                                               └─ API с токеном учителя
                                                          ▲
Виджет на компьютере учителя ──── запрашивает ───────────┘
  ├─ счётчик у урока
  ├─ список приславших
  └─ «Распаковать»: скачать → распаковать → подтвердить получение
```

- Бот и API — отдельный проект (`homework-bot`), TypeScript.
- VPS: домен и HTTPS-сертификат (Let's Encrypt) для webhook MAX.
- API: список присланных работ с заданного момента, скачивание архива, подтверждение получения. Доступ только по токену учителя.
- После подтверждения получения архив удаляется с VPS. Неполученные архивы хранятся не дольше 30 дней.
- Настройки модуля в виджете: включение, адрес сервера, токен, папка ДЗ, количество учеников в каждом классе.

## Известные ограничения

- Без списка класса виджет не показывает, кто **не** прислал работу, — только общее количество.
- Опечатка в имени (`Иваноф` вместо `Иванов`) даёт в списке отдельного ученика, и счётчик может превысить реальное число сдавших.
- Работу, присланную после начала урока, виджет относит к следующему уроку этого класса.

## Перед запуском

- Зарегистрировать бота на платформе MAX и пройти модерацию.
- Получить письменное согласие родителей на обработку данных учеников.
- Арендовать VPS в России, настроить домен и HTTPS.

## Этапы

1. **Пилот бота** — без изменений в виджете: бот принимает архивы и складывает их на VPS. Несколько недель с одним классом, чтобы проверить, что ученики пользуются ботом и соблюдают формат имени.
2. **API** для получения списка работ и архивов.
3. **Модуль в виджете** — счётчик у урока, список приславших, распаковка. Выпускается как экспериментальная опция.
